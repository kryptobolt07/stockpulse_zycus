The Commercial Problem & Strategic Solution

❌ The Commercial Pain Point

Traditional e-commerce pricing and replenishment decisions lag by days. When products go viral on social media, stock depletes at flat baseline prices, leaving thousands of dollars in surge margin on the table. Conversely, when stock drops critically low, merchandisers debate prices manually over spreadsheets, risking stockouts and unfulfilled backorders.

✅ The StockPulse Solution

StockPulse automates the entire Signal → AI Evaluation → Human Approval loop. Customer order ingestion is decoupled from LLM inference. In the background, Gemini 2.5 Flash analyzes burn runway, supplier lead times, and category velocity, queuing structured proposals with confidence scores and explainable business reasoning.

Backend Structure & Architectural Layers

StockPulse's backend is built with Java 21 and Spring Boot 3.3.4 using Domain-Driven Design (DDD) and the Controller-Service-Repository pattern. It is designed so that even someone new to enterprise architecture can follow the exact flow of data.

🎓 Student / Beginner's Guide: How the 5 Backend Layers Work Together
1. Controllers (`/controller`)

The "front desk" of the server. They receive HTTP requests from the React frontend (e.g. POST /products/1/orders), validate input fields, and pass work to the Service layer.

2. Services (`/service`)

The "business brain". Handles database updates, checks inventory thresholds, and fires background events when an order creates a stock alert or surge.

3. Agent Engine (`/agent` & `/ai`)

Asynchronous background workers. Listens to events, crafts prompts with category benchmarks, calls the LiteLLM Gateway (Gemini 2.5 Flash), and clamps bounds.

4. Repositories (`/repository`)

Spring Data JPA interfaces that talk directly to the H2 database, providing instant CRUD queries and custom average velocity aggregation.

Database Usage & Seed Data (Addendum A)

StockPulse utilizes an embedded H2 In-Memory Relational Database configured with JPA/Hibernate. This enables instant setup with zero external database dependencies.

1. `products` Table

Stores primary catalog items: id, sku, name, category, current_price, stock_level, reorder_threshold, demand_velocity, status, and Sprint 2 extension fields (cost_price, margin_floor, supplier_id).

2. `pricing_suggestions` Table

Stores AI/Rule pricing proposals: product_id, current_price, recommended_price, change_direction, confidence, reasoning, status (PENDING, ACCEPTED, REJECTED), trigger_reason.

3. `reorder_suggestions` Table

Stores replenishment proposals: product_id, current_stock, recommended_quantity, suggested_lead_time_days, confidence, reasoning, status, trigger_reason.

Dual-Strategy Policy Engine: Mathematical Formulation

StockPulse implements the Strategy Pattern with two swappable commerce advisors switchable at runtime with zero downtime:

1. Deterministic Rule-Based Engine Algorithmic

A deterministic baseline for high-throughput execution, unit testing, or offline fallback when API limits are exceeded:

Low Stock Pricing Hike $$P_{\text{new}} = P_{\text{curr}} \times 1.10$$
Demand Surge Pricing Hike $$P_{\text{new}} = P_{\text{curr}} \times 1.05$$
Replenishment Quantity $$Q_{\text{reorder}} = \max(1, (3 \times T_{\text{threshold}}) - S_{\text{curr}})$$
Category Lead Times $$\text{ELEC: } 7\text{d}, \text{ APP: } 10\text{d}, \text{ HOME: } 14\text{d}$$
2. Contextual AI Commerce Advisor Gemini 2.5 Flash

Context-aware dynamic modeling leveraging multi-factor trade-offs across velocity, margin floors, and inventory runway:

Dynamic Surge Elasticity $$\Delta P \in [+4\%, +15\%] \text{ if } V > 2.0 \times \bar{V}_{\text{cat}}$$
Low Stock Dilemma $$\text{Defensive Hike } (+12\%) \text{ vs Clearance } (-15\%)$$
Dynamic Reorder Quantity $$Q = \text{LeadTime} \times V_{\text{forecast}} + \text{SafetyStock}$$
Confidence Estimation $$\text{Conf} \in [0.0, 1.0] \text{ (Multi-factor score)}$$
🛡️ Sane Bounds & Mathematical Guardrails

To guarantee enterprise safety and prevent hallucinated pricing spikes or infinite reorder quantities, all recommendations must strictly pass an automated clamping filter:

Price Safety Guardrail $$P_{\text{clamped}} = \min\Big(\max(P_{\text{rec}}, 0.30 \times P_{\text{curr}}), 3.00 \times P_{\text{curr}}\Big)$$
Quantity Safety Guardrail $$Q_{\text{clamped}} = \min\Big(\max(1, Q_{\text{rec}}), 50 \times T_{\text{threshold}}\Big)$$
Margin Floor Protection $$P_{\text{clamped}} \ge \text{MarginFloor} \quad (\text{if specified})$$

State Machines & Domain Model Lifecycle

StockPulse enforces strict finite state machines for Products, Pricing Proposals, and Replenishment Suggestions:

Product Lifecycle

ACTIVE → PRICE_REVIEW_PENDING → ACTIVE
(Transitions to OUT_OF_STOCK when stock level drops to 0).

Pricing Suggestion

PENDING → ACCEPTED (updates product price live) | REJECTED (dismisses proposal).

Reorder Suggestion

PENDING → ACCEPTED (simulates inbound shipment receiving) | REJECTED.

One-Line Quickstart & Local Setup

StockPulse requires Java 21 (JDK) and Node.js 18+.

⚡ Option A: Rapid Terminal Launch
# 1. Start Spring Boot Backend (Port 8080)
cd backend && mvn spring-boot:run

# 2. In a separate terminal, start React Frontend (Port 5173)
cd frontend && npm install && npm run dev
📦 Option B: Run Tests & Production Build
# Run Backend Test Suite (9/9 Unit & Integration Tests)
cd backend && mvn test

# Compile Production Frontend Bundle
cd frontend && npm run build

Judge / Evaluator Fast-Track (The 3-Minute "Wow" Test)

Follow these 4 simple steps in the web console (http://localhost:5173) to verify the full reactive agent loop:

Step 1: Trigger Autonomous Demand Spike

In the Catalog table, find PRD-008 (Hoodie — Heather Grey). Click the cyan `Surge (+5)` button twice.

Expected Behavior
Order is acknowledged immediately in <10ms. The top activity banner flashes "AI Agent Evaluating..." and within ~300ms, an AI price increase proposal (+14.5%) appears automatically in Pending Approvals with badge DEMAND SPIKE.
Step 2: Trigger Low Stock Replenishment

Find PRD-003 (Organic Cotton T-Shirt). Click `1x Sale` until stock drops below threshold (≤ 15 units).

Expected Behavior
The agentic loop automatically generates a replenishment proposal (e.g. +37 units with 10d freight lead time) with badge LOW STOCK TRIGGER.
Step 3: Human Governance One-Click Sign-off

In the Pending Approvals queue, click `Apply Price` on the surge card.

Expected Behavior
The proposal status transitions to ACCEPTED, and the live catalog price updates instantly in the database and UI without a page reload.
Step 4: Live Token Stream & Strategy Switch

Click `Stream AI` on any row to watch the LLM reason token-by-token live over SSE. Toggle `Rule Engine` in the top navbar to verify zero-downtime offline fallback.

Hackathon Compliance & Honesty Disclosure

100% Solo Build During Hackathon Sprint

Every line of domain modeling, asynchronous event handling, LiteLLM gateway integration, guardrail policies, and responsive React frontend was authored from scratch during the hackathon sprint following clean architecture and DDD principles.

Intentional Engineering Trade-offs Under Time Limit:

  • In-Memory H2 DB: Selected over external PostgreSQL to provide zero-friction, one-command evaluation for judges with automated Addendum A seed data.
  • Pluggable Strategy Registry: Built with interface abstraction (CommerceAdvisor) to allow dynamic switching between AI and deterministic algorithms without restart.
  • Sprint 2/3 Extension Points: The schema already provisions nullable fields for costPrice, marginFloor, and supplierId ready for multi-echelon supply chain expansions.
